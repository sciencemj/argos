## 수정 후 재검증

Canvas의 `GET /api/v1/files/:id/public_url`이 반환하는 학교 저장소 서명 주소를 사용하도록 변경했다. 학교 로그인은 브라우저 탭 안에 유지한다. 로컬 Argos가 지정된 저장소에서 쿠키·인증 헤더 없이 받으며 리다이렉트는 허용하지 않는다. 저장소 호스트·버킷·파일 ID를 검증하고, 서명 주소는 DB·활동 로그·확장 상태에 남기지 않는다. 데스크톱 HTTP 요청 로그의 저장소 URL 쿼리도 제거한다.

기존 확장 권한으로 현재 수집 함수를 실행하고 임시 Argos 서버와 별도 DB(`/tmp/argos-lms-live-recheck`)로 검증했다. 설치 앱·확장 연결 설정은 바꾸지 않았다.

## 실제 로그인 세션 검증

기존에 설치한 Chrome 확장 프로그램의 권한으로 현재 `collectLms`와 `downloadMaterial` 함수를 실행했다. 확장 프로그램 설정과 설치 앱을 바꾸지 않고, 별도 임시 Argos 서버(127.0.0.1:18100)와 DB에 자료 한 개만 저장하도록 검증 화면을 사용했다. 검증 후 해당 화면·임시 스크립트·서버를 정리했다.

대상: 비즈니스애널리틱스II의 `Week 01-1 Course Introduction.pdf`, 메타데이터 크기 350,665 bytes.

| 단계 | 결과 |
| --- | --- |
| 실제 자료 메타데이터 수집 | 성공, 조회 경고 0개 |
| 대상 자료 메타데이터를 임시 Argos에 저장 | 성공, created 1 |
| 다운로드 필요 여부 조회 | 성공, 대상 자료 반환 |
| 현재 `downloadMaterial`로 파일 다운로드 | 실패, `Failed to fetch` |
| 파일 저장·반복 수집 중복 방지 | 실제 환경에서 미검증, 다운로드 실패로 도달하지 못함 |

다운로드 시작 주소는 `mylms.korea.ac.kr`이다. 같은 URL을 `redirect: "manual"`로 조회했을 때 `opaqueredirect`(status 0)가 반환되어 리다이렉트를 확인했다. Chrome 콘솔에 `kr.object.gov-ncloudstorage.com`의 해당 PDF 요청 실패가 나타났다. 서명된 다운로드 URL이나 쿠키·연결 코드는 이 기록에 포함하지 않았다.

`integrations/learningx-extension/collector.js`의 다운로드 요청은 `redirect: "error"`를 사용하므로 이 학교의 외부 저장소 이동을 지원하지 못한다. 임시 DB를 확인한 결과 메시지 1개, 첨부 0개, 파일 0개였다. 자동 테스트는 같은 출처에서 직접 파일을 반환하는 모의 응답을 사용하므로 실제 리다이렉트 경로를 검증하지 못한다.

초기 검증 당시에는 제품 코드를 수정하지 않았다. 이후 사용자의 수정·재검증 요청에 따라 위 방식으로 수정하고 재검증했다.
