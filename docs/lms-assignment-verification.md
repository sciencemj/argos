# LMS 과제 본문·과목 자료 컨텍스트 실검증 — 2026-10-13

Phase 16c·16d를 실제 고려대 LMS(`mylms.korea.ac.kr`) 로그인 세션으로 확인했다.

## 방법

- 별도 Argos 서버(`127.0.0.1:18100`)와 임시 데이터 폴더를 썼다. 설치 앱(8000)·개발 DB·Chrome에 설치된 확장 설정은 바꾸지 않았다.
- Orca 내장 브라우저에서 사용자가 직접 로그인한 탭에 저장소의 현재 `collectLms('sync')`를 실행했다(GET만). 결과를 연결 코드로 임시 서버 `/lms/import`에 보냈다.
- 검증 후 서버·탭·임시 DB·수집 결과 파일을 지웠다.

## 확인 중 고친 것

- 본문 링크 중 학교 다른 시스템 주소에 `authkey`·`user_id` 쿼리가 있었다. 수집 단계에서 인증·사용자 식별로 보이는 쿼리(`auth`, `token`, `key`, `sig`, `session`, `pass`, `secret`, `user_id`, `uid`)를 지운다. 재수집 결과 해당 과제 1건만 갱신되고 키는 남지 않았다.
- 최근 활동(전체의 대부분)이 같은 공지·과제의 중복 알림인데 원본보다 위에 나왔다. 검색 점수를 절반으로 하고 컨텍스트의 "그 밖의 최근 자료" 목록에서 뺐다(검색으로는 여전히 찾음).
- 제출 방식 `not_graded`가 영어로 남아 이름표를 추가했다(`wiki_page`, `student_annotation` 포함).

## 한계

- 실제 에이전트 답변(모델이 출처를 밝히는지)은 이번 검증에 포함하지 않았다. 컨텍스트에 들어가는 내용까지만 확인했다.
- 주차학습 자료(`materials`)는 이번에 수집하지 않았다(기존 검증: [자료 검증 기록](lms-materials-verification.md)).
- Chrome에 설치된 확장은 저장소 폴더를 직접 불러온 것이라 자동 갱신되지 않는다. 새 수집 코드를 쓰려면 `chrome://extensions`에서 새로고침해야 한다.
